# BLACKHOLE Model Card Template

## Identity and release evidence

Record model/adapter name and version, exact code revision, checkpoint SHA-256, release date, license selected by the owner and whether weights are trained or empty. Link the run manifest and verified evaluation IDs.

## Architecture and numeric semantics

Document layer topology, tokenizer, context length, exact total/trainable parameter counts, ternary/binary/floating-point behavior, FP32 shadow/optimizer states and packed inference format. Distinguish measured properties from inherited starter claims.

## Data and training

List dataset IDs, immutable revisions, licenses/attribution, role/splits, preprocessing version, hashes, sample/token budgets, seed, optimizer, steps, hardware and actual wall time/cost when known.

## Evaluation, intended uses and limitations

Report held-out loss and generation results with prompt-set/checkpoint hashes. State intended research uses, unsupported uses, safety status, language coverage, known failure modes and limitations. Do not infer conversation quality from loss or claim novelty/commercial readiness without evidence.
